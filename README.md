# Adrobot

Обёртка над Keitaro для создания кампаний и редактирования офферов с локальными
черновиками. Приложение работает с реальным Keitaro Admin API.

**Backend:** Python 3.12, FastAPI, SQLAlchemy 2, SQLite.  
**Frontend:** Vue 3, TypeScript, Vite.

## Настройка и запуск

Нужны Python 3.12+ и Node.js 22 LTS. Команды выполняются из корня проекта.

1. Создайте виртуальное окружение и установите зависимости:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
   ```

2. При первом запуске скопируйте `.env.example` в `.env` и укажите API-ключ.
   Если `.env` уже настроен, используйте его.

   ```dotenv
   KEITARO_URL=https://tlgk.host
   KEITARO_API_KEY=your-api-key
   KEITARO_TIMEOUT=20
   DATABASE_URL=sqlite:///./adrobot.db
   CAMPAIGN_NAME_PREFIX=test_bakhshyan_
   APP_TOKEN=
   ```

3. Соберите frontend и запустите backend:

   ```powershell
   cd frontend
   npm ci
   npm run build
   cd ..
   .\run.ps1
   ```

Приложение: **http://127.0.0.1:8000**.  
Swagger приложения: **http://127.0.0.1:8000/docs**.

В Linux/macOS вместо `run.ps1`:

```bash
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

API-ключ хранится в `.env`, который исключён из Git, и передаётся в Keitaro из backend
через заголовок `Api-Key`. Логин и пароль от админки для работы приложения не нужны.
После изменения `.env` перезапустите backend.

### Разработка frontend

Запустите backend на порту 8000 и `npm run dev` в `frontend/`. Vite проксирует `/api`
на backend. При обычном запуске FastAPI раздаёт собранный `frontend/dist` с одного адреса.

### Docker

Настройте `.env`, затем выполните:

```bash
docker compose up --build
```

Приложение доступно на порту 8000; база хранится в томе `adrobot-data`.
Docker-конфигурация подготовлена, но её запуск в текущем окружении не проверялся.

## Работа с кампаниями

### Создание

Укажите название, ISO-коды стран, оффер, домен, группу и источник. Справочники и поиск
офферов используют реальный API. Названия получают префикс `test_bakhshyan_`, например
`test_bakhshyan_campaign1`. Форма показывает префикс отдельно от вводимой части;
backend добавляет его и при прямом запросе API, не дублируя уже указанный префикс.

Кампания создаётся отключённой. Первый поток с геофильтром перенаправляет выбранные
страны на `https://google.com`. Второй поток типа `default` направляет остальных
посетителей на выбранный оффер. После настройки обоих потоков кампания включается.
При ошибке настройки выполняется компенсирующее архивирование созданной кампании.

### Редактор

- В списке кампаний доступны поиск по названию или ID и фильтры **Все / Мои / Черновики**.
  «Мои» показывает кампании с настроенным префиксом `test_bakhshyan_`.
- **Синхронизировать (Fetch streams)** загружает актуальную конфигурацию из Keitaro и сохраняет базовый
  снимок. Технические потоки показываются отдельно; их правила в приложении не редактируются.
- **Добавить оффер** создаёт локальное изменение и пересчитывает доли.
- **Удалить / Вернуть** переносит оффер в местный архив с долей 0% или восстанавливает
  его без дублирования. Сам оффер из каталога Keitaro не удаляется.
- В каждом потоке есть поиск офферов и сворачиваемый архив. Поиск учитывает архивные
  записи; после удаления оффера архив раскрывается автоматически.
- **Pin** сохраняет долю при пересчёте остальных офферов. Ввод нового значения доли
  также закрепляет её.
- **Отменить (Cancel)** после подтверждения возвращает последний успешно загруженный или
  опубликованный снимок. Новые связи из отменённого черновика исчезают.
- **Опубликовать (Push to Keitaro)** проверяет состав, доли и доступность офферов, затем обновляет
  только поле `offers` потока. Фильтры, лендинги и остальные настройки сохраняются.
  Публикация подтверждается контрольным чтением API.
- **История** показывает последние 100 действий выбранной кампании.

Редактирование офферов до Push выполняется локально. Черновики, архив и закреплённые
доли сохраняются в SQLite между обновлениями страницы и перезапусками приложения.
Создание кампании и Push изменяют данные в реальном Keitaro.

### Синхронизация и ошибки

Повторный Fetch сопоставляет записи по идентификаторам Keitaro. Отсутствующие офферы
переходят в местный архив; отсутствующие потоки сохраняются как удалённые в источнике.
Если есть черновик, интерфейс показывает расхождения и предлагает сохранить его либо
явно отменить и загрузить состояние Keitaro.

Ошибка Push сохраняет черновик. Если ответ на PUT потерян, повторный Push распознаёт
уже применённый состав и подтверждает его чтением. Внешняя правка состава после
последнего Fetch блокирует публикацию и требует сверки.

Автоматических повторов создания кампаний нет: после неоднозначного сетевого сбоя
сначала проверьте список в Keitaro.

### Доли трафика

Доли задаются целыми процентами, как в официальной OpenAPI-схеме Keitaro и проверенных
ответах API этой установки. Закреплённые доли сохраняются; остаток делится между
незакреплёнными офферами. Неделимые процентные пункты получают первые офферы по текущему
порядку. Например, Pin 25% и два других оффера дают **25 / 38 / 37**, сумма 100%.

Если закреплённые доли превышают 100% или все доли закреплены с суммой меньше 100%,
операция отклоняется. Пустой состав офферов можно опубликовать: в Keitaro отправляется
`offers: []`, а удалённые офферы сохраняются в местном архиве для восстановления.
Проверка суммы 100% применяется к потокам, в которых остаются активные офферы.

## Структура проекта

```text
backend/
  api/                 маршруты, авторизация и зависимости запросов
  domain/offers.py     типы снимков и расчёт распределения долей
  integrations/        клиент Keitaro Admin API и HTTP-транспорт
  services/            создание, синхронизация, редактирование и история
  models.py            SQLAlchemy-модели
  schemas.py           валидация входящих запросов
  database.py          engine и сессии
  migrations.py        перенос старой локальной схемы с резервной копией
  main.py              сборка FastAPI-приложения
frontend/src/
  components/          части интерфейса с типизированными props и events
  views/               форма создания и редактор кампании
  composables/         состояние рабочего пространства и API-операции
  api.ts               типизированный HTTP-клиент приложения
  types.ts             контракт данных frontend/backend
  styles/              общие, тематические и адаптивные стили
tests/
  fixtures/            данные для изолированных тестов
  fakes.py             тестовая подстановка транспорта Keitaro
```

HTTP-запросы вынесены из Vue-шаблонов. Backend отделяет доменные ошибки от FastAPI,
а транспорт API — от сценариев приложения. Произвольные поля Keitaro сохраняются
в исходном JSON; локальные снимки офферов имеют явный тип `OfferSnapshot`.

При обновлении со старой схемы SQLite приложение сначала создаёт резервную копию
`*.before-live-only-*.db` рядом с базой. Затем переносит реальные кампании, черновики,
архив и историю с сохранением идентификаторов и ревизий в схему с одним источником.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check backend tests
.\.venv\Scripts\python.exe -m ruff format --check backend tests
cd frontend
npm run typecheck
npm test
npm run format:check
npm run build
```

Тесты используют отдельную временную БД и подставной транспорт из `tests/`.
Они не обращаются к реальному трекеру и не изменяют его кампании.
Покрываются черновики, архив, Pin, балансировка, конфликты, ошибки API и повторный Push.
Frontend-тесты проверяют выбор и фильтрацию кампаний, поиск и восстановление офферов,
а также блокировку публикации при неверном распределении. Они выполняются в jsdom без
подключения к Keitaro.

Форматирование: `ruff format backend tests`, `npm run format`.
Настройки: `pyproject.toml`, `.prettierrc.json`, `.editorconfig`.

## Ограничения запуска

Приложение рассчитано на один процесс backend (`--workers 1`). SQLAlchemy проверяет
ревизии снимков, а блокировка сериализует локальные изменения и публикации.
Внешняя правка между контрольным GET и PUT остаётся ограничением интеграции;
для нескольких процессов потребуется распределённая блокировка.

Сервер по умолчанию слушает localhost. Для удалённого доступа задайте `APP_TOKEN` и
используйте HTTPS через reverse proxy. Токен приложения хранится в sessionStorage
вкладки; ключ Keitaro остаётся на сервере.
